## What is real

The **schema** is exact. These files were not hand-written: the generator builds
a real `PredictionStore` and calls the same `mipa.metrics`
functions the production `analyze` command calls. Column names, column order,
dtypes, rounding, and the null convention for a failed parse are what you will
actually receive.

The **dimensions** are exact too — 500 notes × 3 models × 28 conditions × 16
phenotypes = **672,000 predictions**, the real run's size. Code that works here
will work on the real output without a reshape, and will have been exercised at
true scale.

Phenotype prevalences are the real ones from the 1,388-note MIPA corpus, so the
rare phenotypes are genuinely rare here (`c_diff_complication` has 24 positives)
and any code that breaks on a small denominator will break now rather than later.

### `predictions.csv.gz` — start here

`document_id, model, condition, corruption, severity, phenotype, y_true, y_pred,
parse_status`

Everything else is an aggregate of this. You need it for anything with
note-level structure: paired tests across the 500 notes, bootstrap CIs
resampling *notes* rather than pairs, or mixed-effects models with random
intercepts per note and per phenotype.

`y_pred` is **empty** where `parse_status != "ok"`. Those rows are kept
deliberately — filter them if you want, but you cannot see that the denominator
moved if they were never written.

```python
import pandas as pd
p = pd.read_csv("predictions.csv.gz")            # 672k rows, ~30 MB in memory
ok = p[p.parse_status == "ok"]
```

### `robustness_deltas.csv` — the headline

One row per model × corruption × severity × metric, where metric ∈ {`macro_f1`,
`micro_f1`, `accuracy`, `macro_recall`, `micro_recall`}.

- `delta` = `corrupted` − `baseline`. **Negative means degradation.**
- `delta_pct` = relative change. Written **empty when `baseline` is 0**, never
  `inf` or `nan` — that case does not arise in this mock, so handle it from the
  contract rather than from the data.
- `n_paired` / `n_dropped` — both arms are scored on exactly the pairs *both*
  answered. If a corrupted arm loses 3% of pairs to parse failures, comparing its
  97% against the baseline's 100% would compare two different denominators, so
  the delta table intersects them first.
- `parse_failure_rate` — the corrupted arm's, so you can see what pairing cost.

`overall_metrics.csv` deliberately does **not** pair: it reports each arm on its
own evaluable pairs, which is the right marginal number and the wrong difference.
The two tables answer different questions; don't mix them.

## Structure the mock deliberately contains

Your pipeline should recover all of this. If it doesn't, the pipeline is wrong —
which is the point of a mock with known ground truth.

| | |
|---|---|
| baseline macro-F1 | 0.48 / 0.60 / 0.63 for 4b / 12b / 27b |
| severity | monotone in **27/27** model × corruption cells, all metrics |
| basket | character corruptions ≈ 2–3× the damage of structural ones |
| model | relative degradation −12.6% / −10.7% / −6.8% — bigger is more robust |
| parse failures | rise with severity (0% → 0.6%), worst on the smallest model |
| macro vs micro | diverge sharply; prevalence spans 6% to 68% |

One subtlety worth handling on purpose: **absolute and relative degradation can
disagree.** F1 is nonlinear in recall, so a model with a higher baseline can show
a larger absolute drop from a smaller relative one. Decide which you are
reporting before you look at the real numbers.

## Regenerating

```bash
python analysis/make_sample_output.py --out sample_output      # 500 notes, ~2 min
python analysis/make_sample_output.py --out small -n 50        # quick iteration
```

Deterministic — BLAKE2b-keyed, no RNG seed — so two people regenerating get
byte-identical files and any diff is a real diff.

## What will differ in the real output

- `document_id` will be a MIMIC-IV `hadm_id` (8-digit integer), and the files
  will then be **restricted under the PhysioNet DUA**.
- `parse_failures.csv` will contain real model text about real clinical notes.
  It is the one output that is not safe to circulate.
- Effects will be noisier and may be non-monotone, absent, or in an unexpected
  direction. The mock is legible by construction; reality is not obliged to be.
